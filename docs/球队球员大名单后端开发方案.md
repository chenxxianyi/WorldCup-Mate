# WorldCup Mate 球队球员大名单后端开发方案

## 1. 后端目标

为球队详情页提供稳定的球员大名单数据能力。

第一版后端需要支持：

- 新增球员数据模型和数据表。
- 根据球队 ID 查询该球队球员大名单。
- 返回球员名字、号码、照片、位置等字段。
- 支持后续通过官方名单、JSON、SQL 或第三方 API 导入和同步数据。
- 接口失败或名单为空时不影响球队详情、赛程、积分等现有核心功能。

## 3. 数据模型设计

新增模型文件：

```text
backend/internal/models/player.go
```

建议模型：

```go
package models

import (
	"time"

	"gorm.io/gorm"
)

type Player struct {
	ID             uint           `gorm:"primaryKey" json:"id"`
	TeamID         uint           `gorm:"index;not null" json:"team_id"`
	Team           Team           `gorm:"foreignKey:TeamID" json:"team,omitempty"`
	Name           string         `gorm:"size:100;not null;index" json:"name"`
	NameEn         string         `gorm:"size:100;index" json:"name_en"`
	ShirtNumber    int            `gorm:"index" json:"shirt_number"`
	Position       string         `gorm:"size:20;index" json:"position"`
	PositionLabel  string         `gorm:"size:20" json:"position_label"`
	PhotoURL       string         `gorm:"size:500" json:"photo_url"`
	Club           string         `gorm:"size:100" json:"club"`
	Source         string         `gorm:"size:50;index" json:"source"`
	SourcePlayerID string         `gorm:"size:100;index" json:"source_player_id"`
	CreatedAt      time.Time      `json:"created_at"`
	UpdatedAt      time.Time      `json:"updated_at"`
	DeletedAt      gorm.DeletedAt `gorm:"index" json:"-"`
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `team_id` | 关联球队 |
| `name` | 前端展示名 |
| `name_en` | 英文名或原始名 |
| `shirt_number` | 球衣号码 |
| `position` | 标准位置编码，如 `GK`、`DF`、`MF`、`FW` |
| `position_label` | 中文位置，如门将、后卫、中场、前锋 |
| `photo_url` | 球员照片 URL，允许为空 |
| `club` | 所属俱乐部，可选 |
| `source` | 数据来源，如 `fifa_official`、`balldontlie` |
| `source_player_id` | 来源系统球员 ID，用于去重和同步 |

建议索引：

- `team_id`
- `position`
- `shirt_number`
- `source + source_player_id`

如果名单数据质量稳定，可以增加唯一约束：

```text
team_id + shirt_number
```

如果号码可能缺失或不稳定，则使用：

```text
team_id + name_en
```

import (
	"worldcup-mate/internal/database"
	"worldcup-mate/internal/models"
)

func ListPlayersByTeam(teamID uint) ([]models.Player, error) {
	var players []models.Player
	err := database.DB.
		Where("team_id = ?", teamID).
		Order("shirt_number ASC, id ASC").
		Find(&players).Error
	return players, err
}

## 7. Handler 和接口设计

可以新增：

```text
backend/internal/handlers/player_handler.go
```

也可以第一版放在：

```text
backend/internal/handlers/team_handler.go
```

推荐新增 handler，避免 `team_handler.go` 继续膨胀。

接口：

```http
GET /api/teams/:id/players
```

返回示例：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "id": 1,
      "team_id": 10,
      "name": "Kylian Mbappe",
      "name_en": "Kylian Mbappe",
      "shirt_number": 10,
      "position": "FW",
      "position_label": "前锋",
      "photo_url": "https://example.com/player.jpg",
      "club": "Real Madrid"
    }
  ]
}
```

Handler 示例：

```go
func GetTeamPlayers(c *gin.Context) {
	teamID, err := strconv.ParseUint(c.Param("id"), 10, 32)
	if err != nil {
		utils.Error(c, 400, "invalid team id")
		return
	}

	players, err := services.ListPlayersByTeam(uint(teamID))
	if err != nil {
		utils.Error(c, 500, err.Error())
		return
	}

	utils.Success(c, players)
}
```

## 9. 数据导入方案

### 9.1 第一版推荐：离线 JSON 导入

新增数据文件：

```text
backend/data/players_2026.json
```

示例：

```json
[
  {
    "team_code": "FRA",
    "name": "Kylian Mbappe",
    "name_en": "Kylian Mbappe",
    "shirt_number": 10,
    "position": "FW",
    "position_label": "前锋",
    "photo_url": "",
    "club": "Real Madrid",
    "source": "fifa_official"
  }
]
```

导入逻辑：

1. 读取 JSON。
2. 通过 `team_code` 匹配 `teams.fifa_code`。
3. 生成 `models.Player`。
4. 按 `team_id + shirt_number` 或 `team_id + name_en` upsert。

### 9.2 可选：SQL seed

如果第一批数据量较少，也可以直接写入：

```text
worldcup_mate.sql
```

不推荐长期依赖 SQL 维护 48 队名单，因为后续更新成本高。

### 9.3 后续：第三方 API 同步

后续可接入：

- BALLDONTLIE World Cup API
- API-Football
- SportMonks
- 其他带球员照片的数据源

建议保留：

- `source`
- `source_player_id`
- `updated_at`

这样可以支持增量同步和来源追踪。

## 10. 错误处理

接口行为建议：

- `team_id` 非法：返回 400。
- 球队不存在但直接查 players 无结果：可以返回空数组。
- 数据库错误：返回 500。
- 没有球员名单：返回空数组，不返回错误。

前端需要根据空数组展示“球员大名单暂未同步”。

## 12. 开发步骤

P0 后端最小闭环：

1. 新增 `models.Player`。
2. `AutoMigrate` 加入 `Player`。
3. 新增 player repository。
4. 新增 player service。
5. 新增 `GetTeamPlayers` handler。
6. 注册 `GET /api/teams/:id/players`。
7. 准备 1-2 支球队测试数据。
8. 手动请求接口确认返回结构。

P1 数据导入：

1. 准备 `players_2026.json`。
2. 编写导入脚本或 seed。
3. 支持 upsert，避免重复导入。
4. 补充 `source` 和 `source_player_id`。

P2 同步增强：

1. 接入第三方 API。
2. 补充照片。
3. 增加定时同步或手动同步命令。
4. 增加同步日志。

## 13. 后端验收标准

- 数据库存在 `players` 表。
- `players.team_id` 能关联现有 `teams.id`。
- `GET /api/teams/:id/players` 可返回球员名单。
- 返回字段包含名字、号码、位置、照片 URL。
- 空名单返回空数组。
- 接口失败不影响球队详情、赛程、积分接口。
- `go test ./...` 通过，或明确记录现有失败项。

## 修订记录：移除演示数据和兜底数据

更新时间：2026-06-05

根据最新要求，后端已调整为真实数据模式：

- 不再向 `players` 表写入任何演示球员数据。
- 不再为球队生成兜底球员名单。
- `GET /api/teams/:id/players` 只返回数据库中真实存在的球员记录。
- 如果某支球队没有球员记录，接口返回空数组 `[]`，不补默认球员、不补默认照片、不补默认位置。
- `backend/internal/database/seed.go` 已移除球员演示种子逻辑。
- 为避免历史启动时写入过演示数据，启动 seed 阶段只会清理 `source = demo_seed` 的旧演示记录，不会创建新的球员记录。
