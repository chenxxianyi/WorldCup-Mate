# WorldCup Mate 比赛首发阵容前端开发方案

## 1. 前端目标

在比赛详情页展示比赛双方的首发阵容、替补席、阵型信息，并为后续 API-Football 站位图增强预留结构。

第一阶段目标：

- 通过 `GET /api/matches/:id/lineups` 读取本地阵容数据。
- 在比赛详情页展示两队阵型、首发 11 人和替补名单。
- 阵容未发布、接口失败、数据为空时只影响阵容区域，不影响比赛详情页其他内容。

第二阶段目标：

- 支持 API-Football 返回的 `grid` 站位字段。
- 在比赛详情页展示球场站位图。
- 优先展示已关联本地 `players` 的中文名、头像、号码和位置。
- 无 `grid` 时按 `formation` 做基础分层回退，仍不可解析时回退列表展示。

## 3. 页面信息结构

阵容模块建议放在 AI 比赛解读之后、小组积分之前。

最终结构：

```text
比赛 Hero
AI 比赛解读
首发阵容
所在小组积分
```

原因：

- 首发阵容是比赛详情的核心信息，应在用户看完比赛基本信息后尽快出现。
- 阵容数据通常临近开赛才可用，独立区域更适合展示“暂未公布”状态。
- 小组积分属于背景信息，优先级低于单场阵容。

## 4. 前端类型设计

新增文件：

```text
frontend/src/types/lineup.ts
```

建议类型：

```ts
export type LineupStatus = 'unavailable' | 'partial' | 'available'
export type LineupSide = 'home' | 'away'
export type LineupRole = 'start_xi' | 'substitute'

export interface ApiLineupPlayer {
  player_id?: number | null
  name: string
  name_en?: string
  shirt_number?: number
  position?: string
  position_label?: string
  role?: LineupRole
  grid?: string
  photo_url?: string
}

export interface ApiTeamLineup {
  team_id: number
  team_name: string
  team_code?: string
  side: LineupSide
  formation?: string
  coach_name?: string
  status?: LineupStatus
  start_xi: ApiLineupPlayer[]
  substitutes: ApiLineupPlayer[]
}

export interface ApiMatchLineups {
  match_id: number
  status: LineupStatus
  source?: 'football-data' | 'api-football' | string
  message?: string
  home: ApiTeamLineup | null
  away: ApiTeamLineup | null
}

export interface LineupPlayer {
  playerId: number | null
  name: string
  nameEn: string
  shirtNumber?: number
  position: string
  positionLabel: string
  role: LineupRole
  grid: string
  photoUrl: string
}

export interface TeamLineup {
  teamId: number
  teamName: string
  teamCode: string
  side: LineupSide
  formation: string
  coachName: string
  status: LineupStatus
  startXi: LineupPlayer[]
  substitutes: LineupPlayer[]
}

export interface MatchLineups {
  matchId: number
  status: LineupStatus
  source: string
  message: string
  home: TeamLineup | null
  away: TeamLineup | null
}
```

转换函数建议保持轻量，只做字段命名转换，不生成虚假球员、虚假头像或虚假位置：

```ts
export function normalizeLineupPlayer(value: ApiLineupPlayer, role: LineupRole): LineupPlayer {
  return {
    playerId: value.player_id ?? null,
    name: value.name || '',
    nameEn: value.name_en || '',
    shirtNumber: value.shirt_number,
    position: value.position || '',
    positionLabel: value.position_label || '',
    role,
    grid: value.grid || '',
    photoUrl: value.photo_url || '',
  }
}
```

## 5. API 设计

推荐新增文件：

```text
frontend/src/api/lineups.ts
```

方法：

```ts
import request from './request'
import type { ApiMatchLineups } from '@/types/lineup'

export function apiGetMatchLineups(matchId: number) {
  return request.get<ApiMatchLineups>(`/matches/${matchId}/lineups`)
}
```

也可以放在 `frontend/src/api/matches.ts` 中，但独立文件更方便后续扩展 admin 同步入口。

## 6. 比赛详情页状态设计

修改：

```text
frontend/src/pages/user/MatchDetailPage.vue
```

新增状态：

```ts
const lineups = ref<MatchLineups | null>(null)
const lineupsLoading = ref(false)
const lineupsError = ref('')
let lineupRequestSeq = 0
```

加载逻辑：

```ts
async function loadLineups(matchId: number) {
  const seq = ++lineupRequestSeq
  lineupsLoading.value = true
  lineupsError.value = ''
  lineups.value = null

  try {
    const res = await apiGetMatchLineups(matchId)
    if (seq !== lineupRequestSeq) return
    lineups.value = normalizeMatchLineups(res)
  } catch {
    if (seq !== lineupRequestSeq) return
    lineupsError.value = '首发阵容加载失败'
  } finally {
    if (seq === lineupRequestSeq) {
      lineupsLoading.value = false
    }
  }
}
```

接入建议：

- 在 `loadMatch()` 成功获取比赛详情后调用 `loadLineups(id)`。
- 切换路由时清空旧阵容状态，避免上一场比赛阵容短暂残留。
- 阵容接口失败时不抛给页面整体错误。

## 7. 首发阵容组件

新增组件：

```text
frontend/src/components/common/MatchLineups.vue
```

Props：

```ts
defineProps<{
  lineups: MatchLineups | null
  loading?: boolean
  error?: string
}>()
```

组件职责：

- 展示整体 loading、error、empty 状态。
- 展示 home / away 两队阵型、教练、首发、替补。
- 第二阶段有站位数据时渲染 `LineupPitch`。
- 数据不足时回退到紧凑列表。

不建议组件做的事：

- 不直接请求接口。
- 不生成兜底球员。
- 不根据号码推断球员身份。
- 不把第三方错误暴露成大段技术文本。

## 8. 第一阶段 UI 设计

### 8.1 桌面端

使用双列布局：

```text
首发阵容
[主队 阵型]                 [客队 阵型]
首发列表                    首发列表
替补席                      替补席
```

单个球员行：

```text
#13  吉列尔莫·奥乔亚        门将
```

展示规则：

- 号码存在时显示 `#13`，不存在时显示空位或 `-`。
- 姓名使用后端返回的 `name`，不在前端自行翻译。
- `position_label` 优先，其次 `position`，都没有则留空。
- 替补列表使用更紧凑行高，避免页面过长。

### 8.2 移动端

推荐使用 tabs 或上下堆叠。

第一版建议上下堆叠：

- 避免 tabs 状态和页面切换复杂化。
- 两队信息都能被搜索和截图完整看到。
- 适合比赛详情页当前移动端结构。

如果后续阵容很长，可改为 segmented control：

```text
[主队] [客队]
```

### 8.3 状态文案

状态建议：

- loading：`正在加载首发阵容...`
- unavailable：`首发阵容暂未公布`
- partial：`阵容信息更新中`
- error：`首发阵容加载失败`
- empty：`暂无阵容数据`

注意：

- 文案只出现在阵容模块内。
- 不要阻断用户查看比分、赛程、积分等信息。

## 9. 第二阶段球场站位图

新增组件：

```text
frontend/src/components/common/LineupPitch.vue
```

Props：

```ts
defineProps<{
  home: TeamLineup
  away: TeamLineup
}>()
```

推荐渲染策略：

1. 两队都有 `startXi` 且至少一队有 `grid` 时展示球场图。
2. 有 `grid` 的球员按 `grid` 定位。
3. 没有 `grid` 但有 `formation` 时按阵型分层定位。
4. 无法定位的球员不强行摆放，仍在列表中展示。

`grid` 解析建议：

```ts
function parseGrid(grid: string) {
  const [row, col] = grid.split(':').map(Number)
  if (!row || !col) return null
  return { row, col }
}
```

坐标规则：

- 主队从下往上攻，客队从上往下攻。
- `row` 映射纵向层级。
- `col` 映射当前层横向位置。
- 同层球员按最大列数均分横向空间。

头像展示规则：

- `photoUrl` 存在时展示真实头像。
- 头像加载失败时隐藏图片并展示号码圆点。
- 没有头像时展示号码圆点。
- 没有号码时展示小圆点，不生成姓名首字母头像。

点击或 hover 球员展示：

- 中文名
- 英文名
- 号码
- 位置

## 10. 样式原则

延续当前项目视觉：

- 使用 `var(--card)`、`var(--card-soft)`、`var(--line)`、`var(--muted)`、`var(--primary)`。
- 阵容模块使用现有 `section` 和 `card` 语义。
- 列表行保持紧凑，不做大块宣传式卡片。
- 移动端 375px 不出现横向滚动。
- 球员姓名允许换行或 `overflow-wrap: anywhere`，不能压破布局。
- 球场站位图使用稳定 `aspect-ratio`，避免图片加载或球员名变化导致布局跳动。

第一阶段建议样式结构：

```css
.lineup-teams {

.lineup-player-row {
```

## 11. 自动刷新策略

首发阵容临近开赛才发布，前端可以做轻量刷新。

建议规则：

- 用户进入比赛详情页时请求一次。
- 如果比赛未开始，且距离开球 90 分钟以内，每 60 秒刷新一次。
- 如果比赛进行中且阵容仍不可用，每 60 秒刷新一次。
- 阵容状态为 `available` 后停止自动刷新。
- 页面卸载或切换比赛时清理定时器。

第一版也可以不做定时器，只依赖用户进入页面和手动刷新页面。若实现自动刷新，必须避免重复定时器。

## 13. 前端验收标准

第一阶段验收：

- 比赛详情页能看到“首发阵容”区域。
- 阵容未公布时展示清晰空状态。
- 接口失败时只显示局部错误，不影响比赛详情页其他内容。
- 有数据时展示主客队阵型、首发和替补。
- 移动端 375px 无横向滚动。
- 切换比赛时不会残留上一场阵容。
- `npm.cmd run build` 通过。

第二阶段验收：

- API 返回 `grid` 时展示球场站位图。
- 球员头像存在时展示真实头像。
- 头像缺失或加载失败时展示号码圆点。
- 没有 `grid` 时仍能回退列表展示。
- 球员名、号码、位置不会互相遮挡。
- 桌面端和移动端站位图尺寸稳定。

## 14. 风险和注意事项

- 世界杯正式比赛前，阵容接口可能长期返回空数据，这是正常情况。
- 前端不要为了“看起来完整”生成假球员、假头像、假位置。
- football-data 和 API-Football 的球员 ID 不一致，前端只消费后端统一后的本地接口。
- 阵容发布后仍可能临场调整，前端需要允许接口数据更新。
- 球场站位图是增强体验，不应替代基础列表；列表必须始终可用。
