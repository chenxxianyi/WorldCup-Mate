# WorldCup Mate 四项新功能开发方案

## 1. 目标

在现有基础上新增四个功能：

1. **一键收藏球队所有比赛**：球队详情页一键批量收藏该队所有未结束的比赛。
2. **近期比赛时间线（首页优化）**：首页改造为「近期时间线」视图，串联过去 48h + 未来 48h 比赛。
3. **淘汰赛对阵图（Bracket）可视化**：从 32 强到决赛的树状晋级图。
4. **比赛数据看板（控球率/射门等）**：比赛详情页展示技术统计数据。

### 2.1 现状

- `MatchCard` 已有单场收藏按钮（`toggleMatchFavorite`）。
- `useFavoriteStore` 已有 `toggleMatchFavorite(matchId)` + `favoriteMatchIds` 状态。
- 前端 `apiAddFavoriteMatch` / `apiRemoveFavoriteMatch` 已可用。
- 后端 `AddFavoriteMatch` repo 使用 `FirstOrCreate`，幂等安全。

### 2.2 前端改动

#### TeamDetailPage.vue

在 hero-actions 区域「关注球队」按钮旁新增「收藏所有比赛」按钮：

```vue
<button
  class="pill-btn"
  :disabled="collectingMatches"
  @click="collectAllTeamMatches"
>
  <span class="material-symbols-outlined">bookmark_add</span>
  {{ collectingMatches ? '收藏中...' : '收藏所有比赛' }}
</button>
```

**核心逻辑**：

```ts
const collectingMatches = ref(false)

async function collectAllTeamMatches() {
  if (!team.value || !auth.isLoggedIn) {
    router.push('/login')
    return
  }

  collectingMatches.value = true
  try {
    // 筛选出该队未结束的比赛
    const targetMatches = sortedMatches.value.filter(
      (m) => m.status !== 'finished' && m.status !== 'cancelled'
    )

    // 批量收藏（不阻塞 UI，逐个调用）
    for (const match of targetMatches) {
      if (!fav.isMatchFavorite(match.id)) {
        await fav.addMatchFavorite(match.id)
      }
    }

    // 刷新收藏状态
    await fav.fetchFavoriteMatches()
  } finally {
    collectingMatches.value = false
  }
}
```

#### useFavoriteStore.ts

新增 `addMatchFavorite` 方法（仅收藏，不切换）：

```ts
async function addMatchFavorite(matchId: number) {
  if (favoriteMatchIds.value.includes(matchId)) return
  favoriteMatchIds.value.push(matchId)
  try {
    await apiAddFavoriteMatch(matchId)
  } catch {
    favoriteMatchIds.value = favoriteMatchIds.value.filter((id) => id !== matchId)
  }
}
```

### 3.1 现状

- Countdown（下一场比赛倒计时）
- Stage progress（赛程进度条）
- 「我的关注赛程」

问题：
- 今日比赛和推荐列表是碎片化的，没有时间感。
- 没有「已完成比赛」的摘要入口。

### 3.3 实现方案

#### 3.3.1 后端新增 API

```
GET /api/matches/timeline?days_back=2&days_ahead=2
```

**需求**：
- 返回时间区间内所有比赛（UTC 当天 ± N 天）。
- 已结束比赛附带是否有赛后摘要的标记。
- 比赛按 `kickoff_time_utc ASC`，结束后按 `kickoff_time_utc DESC`（最新完成的在前）。

**Response**：

```json
{
  "matches": [
    {
      "id": 1,
      "home_team_name": "巴西",
      "away_team_name": "摩洛哥",
      "home_score": 2,
      "away_score": 1,
      "status": "finished",
      "kickoff_time_utc": "...",
      "local_kickoff_time": "06-14 22:00",
      "has_post_match_summary": true,
      ...
    }
  ]
}
```

#### 3.3.2 后端改动

**新增 repo 方法**：

```go
// match_repo.go
func ListMatchesInWindow(start, end time.Time) ([]models.Match, error)
```

SQL：
```sql
WHERE kickoff_time_utc >= start AND kickoff_time_utc < end
ORDER BY
  CASE WHEN status = 'finished' THEN 0 ELSE 1 END,
  CASE WHEN status = 'finished' THEN UNIX_TIMESTAMP(kickoff_time_utc) * -1
       ELSE UNIX_TIMESTAMP(kickoff_time_utc) END
```

## 4. 淘汰赛对阵图（Bracket）可视化

### 4.1 设计

创建一个独立的 Bracket 页面，路由 `/bracket`。

#### 布局策略（移动端优先）

淘汰赛有 7 轮（32→16→8→4→2→季军→冠军），移动端无法平铺 7 列。采用**可滑动 + 分轮切换**方案：

```
┌─────────────────────────────────────┐
│ [32强] [16强] [8强] [半决赛] [决赛] │  ← 轮次切换 tab
├─────────────────────────────────────┤
│                                     │
│  ┌──巴西──┐                         │
│  │        ├──巴西──┐                │
│  └──秘鲁──┘        │                │
│  ┌──法国──┐        ├──巴西──┐       │
│  │        ├──法国──┘        │       │
│  └──埃及──┘                 │       │
│  ┌──阿根廷─┐                ├── ? ──│
│  │        ├──阿根廷─┐       │       │
│  └──丹麦──┘        │        │       │
│  ┌──英格兰─┐        ├───────┘       │
│  │        ├──英格兰─┘               │
│  └──韩国──┘                         │
│                                     │
└─────────────────────────────────────┘
```

- 移动端：每次显示相邻 2 轮，左右滑动切换。
- 桌面端：最多显示 4 轮。

#### 连接线绘制

使用纯 CSS（border + pseudo-elements）绘制 T 型连接线，不依赖 Canvas/SVG。

每个 match slot 结构：
```html
<div class="slot">
  <div class="team top">
    <TeamFlag ... />
    <span class="name">巴西</span>
    <span v-if="score" class="score">2</span>
    <span v-else class="score">-</span>
  </div>
  <div class="connector"></div> <!-- T 型连接线 -->
  <div class="team bottom">
    <TeamFlag ... />
    <span class="name">秘鲁</span>
    <span v-if="score" class="score">1</span>
    <span v-else class="score">-</span>
  </div>
</div>
```

CSS 连接线思路：
```css
.slot {
  position: relative;
}
.slot::before {
  /* 左侧横线（T 的头） */
}
.slot::after {
  /* 从中心向下连到下一轮的竖线 */
}
```

### 4.2 后端

复用现有 `GET /api/matches/by-stage/:stage` 接口，前端依次拉取各轮比赛。

**前端新增 API**（`api/matches.ts`）：

```ts
export function apiGetMatchesByStage(stage: string) {
  return request.get(`/matches/by-stage/${stage}`) as Promise<any>
}
```

**数据获取**：
- 进入 Bracket 页面时，并行请求 7 个 stage：`round_of_32`, `round_of_16`, `quarter_final`, `semi_final`, `third_place`, `final`。
- 不需要新的后端接口。

**Bracket 数据结构**（前端计算）：

```ts
interface BracketSlot {
  id: string               // "r32-1" "r16-1" ...
  round: number            // 1=32强, 2=16强, 3=8强, 4=半决赛, 5=决赛
  roundName: string
  position: number         // 在该轮中的位置，从 1 开始
  homeTeam?: TeamInfo
  awayTeam?: TeamInfo
  homeScore?: number
  awayScore?: number
  status: string
  matchId?: number         // 指向实际 match.id
  nextSlotId?: string      // 指向下一轮连接
}
```

**轮次枚举**：

```ts
const BRACKET_ROUNDS = [
  { key: 'round_of_32', name: '32强', slots: 16 },
  { key: 'round_of_16', name: '16强', slots: 8 },
  { key: 'quarter_final', name: '8强', slots: 4 },
  { key: 'semi_final', name: '半决赛', slots: 2 },
  { key: 'third_place', name: '季军赛', slots: 1 },
  { key: 'final', name: '决赛', slots: 1 },
]
```

**动态构建 brackets**：

由于世界杯实际对阵是预设的（32 强 A1 vs B2, C1 vs D2 等），可以硬编码映射关系。比赛数据拉回来后按位置填充即可。

如果某轮比赛尚未产生（如小组赛阶段淘汰赛还没排），显示灰色占位。

```ts
// 32进16 对阵映射（前 8 组）
```

**MVP 简化**：32 强阶段用 position 填充占位，有数据就显示，没数据就显示 `A1 vs B2` 占位文字。

#### 数据同步

你的数据源是 `football-data.org` 和 `api-football`。两者都有 match statistics 接口：
- football-data.org：`GET /matches/{id}` 返回中包含 `homeTeam`/`awayTeam` 的 statistics（如果有）
- api-football：`GET /fixtures?id={id}` 返回中有 `statistics` 数组

第一版：
- **手动填充**：通过 admin 后台手动编辑比赛统计数据。
- **不自动同步**：避免增加现有 sync job 复杂度。

后续可加入自动同步（P1）。

#### Admin API

新增或扩展 admin 更新接口：

```
PUT /api/admin/matches/:id/score
```

扩展 body 接受 statistics 字段。现有 handler `AdminUpdateMatchScore` 增加统计字段处理。

## 6. 推荐开发顺序

| 优先级 | 功能 | 原因 |
|--------|------|------|
| **P0** | 一键收藏球队所有比赛 | 改动最小（2 个文件），后端零改动 |

## 7. 验收标准

### 一键收藏球队所有比赛

- [ ] 球队详情页「收藏所有比赛」按钮在未结束时可见。
- [ ] 点击后逐场调用收藏 API，按钮显示 loading 文字。
- [ ] 收藏完成后刷新状态，已收藏比赛显示实心星标。
- [ ] 全队比赛已结束时按钮隐藏。
- [ ] 未登录状态下点击跳转登录页。

### 首页时间线

- [ ] 首页显示过去 2 天 + 今天 + 未来 2 天的比赛。
- [ ] 已结束比赛按时间倒序，最新完成的在最上面。
- [ ] 已结束比赛显示比分 + 赛后摘要入口链接。
- [ ] 进行中比赛红色高亮 + 实时比分。
- [ ] 未开始比赛显示开球时间。
- [ ] 桌面端保留侧栏。

### 比赛数据看板

- [ ] finished/live 比赛有统计时显示统计卡片。
- [ ] 无统计时卡片隐藏。
- [ ] 控球率用进度条展示。
- [ ] 数值对比清晰。

### 淘汰赛对阵图

- [ ] `/bracket` 路由正常访问。
- [ ] 移动端支持轮次切换（tab + 滑动）。
- [ ] 每场比赛显示队名/国旗/比分（有数据时）。
- [ ] 无数据比赛显示对阵占位文字。
- [ ] 有晋级关系的比赛通过连接线连接。
- [ ] 点击已确定的球队跳转到球队详情。
